# Golden-тесты форматирования MARC — запуск в Docker

Контейнер: `twlib-frontend-1`, рабочий каталог: `/app`.
Тесты: `tests/tests_marc.py`, записи: `tests/records/*.xml`.

## Прогон всех тестов

```bash
docker exec -ti twlib-frontend-1 python -m unittest discover -s tests -v
```

`/bin/bash -c "…"` не обязателен — он нужен только если внутри контейнера требуются пайпы или редиректы.

## Прогон одной записи

`-k` фильтрует по подстроке имени теста:

```bash
docker exec -ti twlib-frontend-1 python -m unittest discover -s tests -v -k 685147
docker exec -ti twlib-frontend-1 python -m unittest discover -s tests -v -k 684564
```

## Перегенерация эталонов (`--dump`)

Только после **осознанного** изменения формата, не «чтобы позеленело»:

```bash
docker exec -i twlib-frontend-1 python tests/tests_marc.py --dump > golden_dump.txt
```

- `-i` **без** `-t`: TTY при редиректе добавляет `\r` и портит вывод.
- Вставьте вывод в константы `EXPECTED_*` в `tests/tests_marc.py`, просмотрите diff, закоммитьте вместе с кодом.

## Обновление файлов в контейнере

Если каталог проекта примонтирован (bind mount) — правки с хоста видны сразу, копировать ничего не нужно.
Если код вшит в образ:

```bash
docker cp tests/tests_marc.py twlib-frontend-1:/app/tests/tests_marc.py
docker cp tests/records/685147.xml twlib-frontend-1:/app/tests/records/685147.xml
```

## Чтение результата

- `OK` — вывод совпал с эталоном символ в символ.
- `FAILED (failures=N)` — смотрите строку `(record='685147.xml', field='domain2')`: сразу видно, какая запись и какой домен разошлись.
- В diff ниже: `-` — фактический вывод, `+` — ожидаемый, `?` — указатель на конкретный символ (так ловятся лишние пробелы).
- Код возврата: `0` — успех, `1` — есть падения (пригодно для скриптов и CI).

## Рабочий цикл

1. Правите `app/marc.py`.
2. Прогоняете тесты.
3. Красное:
   - регресс → чините код;
   - формат изменён осознанно → `--dump` → обновляете эталоны → прогоняете снова.

## Мелочи

- `-s tests` — путь относительно рабочего каталога контейнера. Если WORKDIR образа другой, добавьте `-w /app`.
- Имя контейнера уточняется через `docker ps`.
- Пути к записям внутри теста считаются от `__file__`, поэтому от текущей директории они не зависят.
